Every request on this page requires a [Bearer API key](/en/api/autentikasi).

One exam result represents one test taken by one participant. The result record is created when the participant is registered for the exam, then updated as the participant takes the test and when the score is calculated. Results that belong to participants deleted from the project are not shown.

## When scores are available

`score` is `null` until the test score is calculated. When that happens depends on the test's scoring method:

| Scoring method | When `score` is filled in |
| --- | --- |
| Question Score Calculation (Sum of Correct/Wrong) | Automatically when the participant finishes the test. |
| Answer Score Calculation (Sum of Answer Scores) | Automatically when the participant finishes the test. |
| Psychometric (Answer Grouping) | Automatically when the participant finishes. `score` is always `0`; results per answer group are not available through the API. |
| IRT (UTBK reference, 0-1000), IRT TKA for SMA/SMK (200-800), IRT TKA for SD/SMP (0-100) | After an admin runs **Calculate Score** → **IRT Calculation** in the admin panel. Until then, `score` is `null`. |
| Manual Scoring | After an admin grades the participant's answers in the admin panel. |

A score can change after it is first published, for example when an admin runs **IRT Calculation** again or recalculates scores. Every change updates `updated_at` and sends an `exam_result.scored` webhook. Use `updated_since` to resync results that have changed.

### `meta_score` structure

`meta_score` is `null` until the score is first calculated. Its contents depend on the scoring method:

| Scoring method | `meta_score` contents |
| --- | --- |
| Sum of Correct/Wrong | `correct`, `incorrect`, `unanswered` (number of questions). |
| Sum of Answer Scores | `correct`, `incorrect`, `unanswered`, and `answer_scores` as an object `{ "<question id>": score }`. |
| Psychometric | `total_answered`, `total_unanswered`. |
| IRT | `correct`, `incorrect`, `unanswered`, `irt_theta` (the participant's ability), `irt_scale` (the scale used: `irt`, `irt_tka_sma` or `irt_tka_sd_smp`), and `difficulty_map` as an object `{ "<question id>": difficulty }`. |

## Exam result endpoints

<Accordion title="GET /exam-results — List exam results">
  Sorted from the most recent result.

  ### Parameters

  | Name | Location | Required | Type | Description |
  | --- | --- | --: | --- | --- |
  | `exam_id` | Query | No | integer | Filters by exam ID. |
  | `participant_id` | Query | No | integer | Filters by participant ID. |
  | `email` | Query | No | email | Filters by participant email (exact match). |
  | `exam_quiz_id` | Query | No | integer | Filters by test ID. |
  | `status` | Query | No | integer | `0` pending, `1` active (not started yet or in progress), `2` finished, `3` rejected. |
  | `min_score` | Query | No | numeric | Minimum score. |
  | `max_score` | Query | No | numeric | Maximum score. |
  | `finished_from` | Query | No | datetime | Earliest finish time, in ISO 8601; must be URL-encoded. |
  | `finished_until` | Query | No | datetime | Latest finish time, in ISO 8601; must be URL-encoded. |
  | `updated_since` | Query | No | datetime | Only results changed since this time; ISO 8601, must be URL-encoded. |
  | `page` | Query | No | integer | Page number. Default `1`. |
  | `per_page` | Query | No | integer | Items per page, `1–100`. Default `25`. |

  ### Example request

  ```bash
  curl -X GET "https://app.indolat.com/api/v1/exam-results?exam_id=12&status=2&min_score=70&page=1&per_page=25" \
    -H "Authorization: Bearer <API_KEY>" \
    -H "Accept: application/json"
  ```
