<Accordion title="POST /participants — Create a participant">
  Participants created through the API are verified straight away. The email is stored in lowercase. If a participant with the same email was previously deleted from the project, that account is restored and updated with the data you send.

  ### Parameters

  | Name | Location | Required | Type | Description |
  | --- | --- | --: | --- | --- |
  | `email` | Body | Yes | email | Must be unique within the project, up to 255 characters. |
  | `name` | Body | Yes | string | Participant name, up to 255 characters. |
  | `password` | Body | Yes | string | 6–255 characters long. |
  | `label_id` | Body | No | integer/null | ID of a label that belongs to the project. |
  | `is_active` | Body | No | boolean | Default `true`. |

  ### Example request

  ```bash
  curl -X POST "https://app.indolat.com/api/v1/participants" \
    -H "Authorization: Bearer <API_KEY>" \
    -H "Accept: application/json" \
    -H "Content-Type: application/json" \
    -d '{
      "email": "budi@sekolah.sch.id",
      "name": "Budi Santoso",
      "password": "rahasia123",
      "label_id": 8,
      "is_active": true
    }'
  ```

  ### Example response

  Status `201`.

  ```json
  {
    "success": true,
    "message": "Peserta berhasil dibuat.",
    "data": {
      "id": 340,
      "name": "Budi Santoso",
      "email": "budi@sekolah.sch.id",
      "is_active": true,
      "is_verified": true,
      "verified_at": "2026-07-30T09:00:00+07:00",
      "label": { "id": 8, "name": "Kelas XII IPA" },
      "created_at": "2026-07-30T09:00:00+07:00",
      "updated_at": "2026-07-30T09:00:00+07:00"
    }
  }
  ```
</Accordion>

<Accordion title="POST /participants/batch — Create or update participants in batch">
  Participants are matched by email. The format of every row is validated first: a single invalid row rejects the whole request with status `422`, and the error key points to that row (for example `participants.3.email`). Once validation passes, each row is processed separately and the outcome is reported per row:

  - `created` — a new participant was created, or a previously deleted participant was restored.
  - `updated` — the participant already exists and `update_existing` is `true`.
  - `skipped` — the participant already exists and `update_existing` is `false`. The item includes a `reason`.
  - `failed` — the row could not be processed. The item includes a `reason` and no `participant_id`.

  <Warning>
    With `update_existing: true`, an existing participant's data is replaced with the row's contents: name, password and label. The label is removed if `label_id` is not sent, and an inactive participant is reactivated.
  </Warning>

  ### Parameters

  | Name | Location | Required | Type | Description |
  | --- | --- | --: | --- | --- |
  | `participants` | Body | Yes | array | Contains 1–500 participants. |
  | `participants.*.email` | Body | Yes | email | Participant email, up to 255 characters. |
  | `participants.*.name` | Body | Yes | string | Participant name, up to 255 characters. |
  | `participants.*.password` | Body | Yes | string | 6–255 characters long. |
  | `participants.*.label_id` | Body | No | integer/null | ID of a label that belongs to the project. |
  | `update_existing` | Body | No | boolean | If `true`, existing participants are updated. Default `false`. |

  ### Example request

  ```bash
  curl -X POST "https://app.indolat.com/api/v1/participants/batch" \
    -H "Authorization: Bearer <API_KEY>" \
    -H "Accept: application/json" \
    -H "Content-Type: application/json" \
    -d '{
      "participants": [
        {
          "email": "budi@sekolah.sch.id",
          "name": "Budi Santoso",
          "password": "rahasia123",
          "label_id": 8
        },
        {
          "email": "siti@sekolah.sch.id",
          "name": "Siti Aminah",
          "password": "rahasia456",
          "label_id": 8
        }
      ],
      "update_existing": false
    }'
  ```

  ### Example response

  ```json
  {
    "success": true,
    "message": "2 peserta dibuat, 0 diperbarui, 0 dilewati, 0 gagal.",
    "data": {
      "created": [
        { "index": 0, "email": "budi@sekolah.sch.id", "participant_id": 340 },
        { "index": 1, "email": "siti@sekolah.sch.id", "participant_id": 341 }
      ],
      "updated": [],
      "skipped": [],
      "failed": []
    },
    "meta": {
      "summary": { "total": 2, "created": 2, "updated": 0, "skipped": 0, "failed": 0 }
    }
  }
  ```
</Accordion>

<Accordion title="PATCH /participants/{id} — Update a participant">
  This endpoint also accepts the `PUT` method.

  ### Parameters

  | Name | Location | Required | Type | Description |
  | --- | --- | --: | --- | --- |
  | `id` | Path | Yes | integer | Participant ID. |
  | `name` | Body | No | string | New name, up to 255 characters. |
  | `password` | Body | No | string | New password, 6–255 characters. |
  | `label_id` | Body | No | integer/null | New label ID, or `null` to remove the label. |
  | `is_active` | Body | No | boolean | New active status. |

  Fields you don't send are left unchanged. The email cannot be changed through the API. A participant with `is_active: false` cannot sign in to the CBT, including through an exam access link.

  ### Example request

  ```bash
  curl -X PATCH "https://app.indolat.com/api/v1/participants/340" \
    -H "Authorization: Bearer <API_KEY>" \
    -H "Accept: application/json" \
    -H "Content-Type: application/json" \
    -d '{
      "name": "Budi Santoso Putra",
      "label_id": 9,
      "is_active": true
    }'
  ```

  ### Example response

  ```json
  {
    "success": true,
    "message": "Peserta berhasil diperbarui.",
    "data": {
      "id": 340,
      "name": "Budi Santoso Putra",
      "email": "budi@sekolah.sch.id",
      "is_active": true,
      "is_verified": true,
      "verified_at": "2026-07-30T09:00:00+07:00",
  ```

<Accordion title="DELETE /participants/{id} — Delete a participant">
  A participant who is still registered for an exam cannot be deleted; the request is rejected with status `409`. Cancel their exam registration first with `DELETE /exams/{exam}/participants/{participant}`.

  ### Parameters

  | Name | Location | Required | Type | Description |
  | --- | --- | --: | --- | --- |
  | `id` | Path | Yes | integer | Participant ID. |

  ### Example request

  ```bash
  curl -X DELETE "https://app.indolat.com/api/v1/participants/340" \
    -H "Authorization: Bearer <API_KEY>" \
    -H "Accept: application/json"
  ```

  ### Example response

  ```json
  {
    "success": true,
    "message": "Peserta berhasil dihapus.",
    "data": null
  }
  ```
</Accordion>
